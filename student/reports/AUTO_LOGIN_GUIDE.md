# نظام التسجيل التلقائي لتقارير الطلاب

## نظرة عامة
تم إضافة ميزة التسجيل التلقائي لنظام التقارير الشهرية للطلاب، بحيث يتم تسجيل دخول الطالب تلقائياً دون الحاجة لإدخال بيانات منفصلة أو اختيار الصف الدراسي.

## الملفات المعدلة

### 1. الملفات الجديدة
- **`student/reports/auto_login.php`**: ملف جديد يتولى عملية التسجيل التلقائي

### 2. الملفات المحدثة
- **`student/portal.php`**: تم تحديث رابط التقارير من `reports/` إلى `reports/auto_login.php`
- **`student/reports/student_grades_new.php`**: تم إضافة دعم GET parameter للسماح بالتسجيل التلقائي

## آلية العمل

### خطوات التسجيل التلقائي

1. **الطالب يضغط على "التقارير الشهرية" من البوابة الرئيسية**
   - الرابط يوجهه إلى `student/reports/auto_login.php`

2. **التحقق من الجلسة**
   - يتحقق النظام من أن الطالب مسجل الدخول في النظام الرئيسي
   - التحقق من `$_SESSION['user_id']` و `$_SESSION['role'] === 'student'`

3. **جلب بيانات الطالب**
   - الحصول على بيانات الطالب من النظام الرئيسي باستخدام `User` class
   - الحصول على بيانات الصف باستخدام `ClassRoom` class

4. **تحديد قاعدة البيانات المناسبة**
   - تحليل اسم الفصل لتحديد الصف الدراسي (١-٦)
   - اختيار قاعدة البيانات المناسبة:
     * **الصف الأول والثاني**: `students_db12_mar`
     * **الصف الثالث**: `students_db3_apr`
     * **الصفوف الرابع والخامس والسادس**: `students_db456_apr`

5. **التحقق من وجود بيانات الطالب**
   - البحث في قاعدة بيانات التقارير باستخدام `username` و `password`
   - إذا وُجد الطالب: تسجيل الدخول تلقائياً
   - إذا لم يُوجد: عرض رسالة خطأ مناسبة

6. **التوجيه إلى صفحة الدرجات**
   - تخزين `student_code` و `stage` في الجلسة
   - إعادة التوجيه إلى `student_grades_new.php?stage=primX`

## تحديد الصف الدراسي

يتم تحديد الصف بناءً على أول رقم في اسم الفصل:

```php
// أمثلة على أسماء الفصول والصفوف المقابلة:
"1/1"  → prim1 → students_db12_mar
"٢/٣"  → prim2 → students_db12_mar
"3/2"  → prim3 → students_db3_apr
"٤/١"  → prim4 → students_db456_apr
"5/4"  → prim5 → students_db456_apr
"٦/٢"  → prim6 → students_db456_apr
```

يدعم النظام الأرقام العربية والإنجليزية:
- أرقام عربية: ١ ٢ ٣ ٤ ٥ ٦
- أرقام إنجليزية: 1 2 3 4 5 6

## رسائل الخطأ

### 1. قاعدة البيانات غير موجودة
عندما لا تكون قاعدة بيانات التقارير متاحة للصف:
```
📋 لم يتم رفع التقارير بعد
عذراً، التقارير الشهرية لهذا الصف غير متاحة حالياً
[زر العودة للوحة التحكم]
```

### 2. بيانات الطالب غير موجودة
عندما لا يكون الطالب مسجلاً في قاعدة بيانات التقارير:
```
⚠️ بيانات غير موجودة
عذراً، لم يتم العثور على بياناتك في نظام التقارير
يرجى التواصل مع إدارة المدرسة
[زر العودة للوحة التحكم]
```

### 3. خطأ في الاتصال
عند حدوث خطأ في الاتصال بقاعدة البيانات:
```
❌ خطأ في الاتصال
حدث خطأ أثناء محاولة الاتصال بقاعدة البيانات
يرجى المحاولة لاحقاً أو التواصل مع الدعم الفني
[زر العودة للوحة التحكم]
```

### 4. الطالب غير مسجل الدخول
إذا لم يكن الطالب مسجل الدخول في النظام الرئيسي:
- إعادة التوجيه إلى صفحة تسجيل الدخول: `login.php`

## متطلبات النظام

### قواعد البيانات المطلوبة
1. **النظام الرئيسي**: `rewards_system`
   - جدول `users`: بيانات الطلاب
   - جدول `classes`: بيانات الصفوف

2. **نظام التقارير**: قواعد بيانات منفصلة
   - `students_db12_mar`: تقارير الصفوف الأول والثاني
   - `students_db3_apr`: تقارير الصف الثالث
   - `students_db456_apr`: تقارير الصفوف الرابع والخامس والسادس

### الجداول المطلوبة في قواعد بيانات التقارير
- جدول `students` مع الحقول:
  - `student_code` (اسم المستخدم)
  - `password` (كلمة المرور)
  - `student_name` (اسم الطالب)
  - `class_name` (اسم الفصل)
  - حقول الدرجات الأخرى...

## ملاحظات مهمة

### 1. التوافق مع النظام القديم
- النظام القديم (اختيار الصف يدوياً) لا يزال يعمل من خلال `index.html`
- الطلاب الذين يدخلون مباشرة من البوابة يحصلون على تجربة تلقائية
- كلا النظامين يستخدمان نفس صفحة الدرجات `student_grades_new.php`

### 2. التزامن بين الأنظمة
يجب أن تتطابق البيانات التالية بين النظام الرئيسي ونظام التقارير:
- **اسم المستخدم**: `users.username` = `students.student_code`
- **كلمة المرور**: `users.password` = `students.password`
- يجب أن تكون كلمات المرور متطابقة تماماً (نص عادي، غير مشفر)

### 3. الأمان
- التحقق من صلاحية الجلسة قبل أي عملية
- استخدام prepared statements لمنع SQL injection
- التحقق من وجود قاعدة البيانات قبل الاتصال
- رسائل خطأ واضحة دون الكشف عن معلومات حساسة

### 4. تجربة المستخدم
- لا يحتاج الطالب لإدخال أي بيانات
- لا يحتاج لاختيار الصف الدراسي
- انتقال سلس من البوابة إلى التقارير
- رسائل خطأ واضحة مع إيموجيات وألوان مميزة
- زر العودة في جميع الحالات

## اختبار النظام

### سيناريوهات الاختبار

1. **الحالة المثالية**
   - طالب مسجل الدخول في النظام الرئيسي
   - بياناته موجودة في قاعدة بيانات التقارير
   - النتيجة: انتقال تلقائي لصفحة الدرجات

2. **قاعدة البيانات غير موجودة**
   - الصف لم يتم رفع تقاريره بعد
   - النتيجة: رسالة "لم يتم رفع التقارير بعد"

3. **بيانات الطالب غير موجودة**
   - الطالب مسجل في النظام الرئيسي فقط
   - النتيجة: رسالة "بيانات غير موجودة"

4. **الطالب غير مسجل الدخول**
   - الوصول المباشر لـ `auto_login.php`
   - النتيجة: إعادة توجيه لصفحة تسجيل الدخول

5. **أخطاء الاتصال**
   - خطأ في بيانات اتصال قاعدة البيانات
   - النتيجة: رسالة "خطأ في الاتصال"

## الصيانة والتطوير المستقبلي

### إضافة صفوف جديدة
عند إضافة صفوف دراسية جديدة:

1. تحديث قاعدة البيانات المناسبة في `auto_login.php`:
```php
elseif (preg_match('/^[٧7]/', $class_name)) {
    $stage = 'prim7';
    $dbname = 'students_db7_xxx';
    $month_name = 'الشهر';
}
```

2. تحديث منطق قاعدة البيانات في `student_grades_new.php`:
```php
elseif ($stage == 'prim7') {
    $dbname = 'students_db7_xxx';
    $title_suffix = '(Prim 7)';
    $month_name = 'الشهر';
}
```

### تغيير قواعد البيانات
إذا تغيرت أسماء أو هيكل قواعد البيانات:
1. تحديث الثوابت في بداية `auto_login.php`
2. تحديث منطق اختيار قاعدة البيانات
3. اختبار جميع السيناريوهات

## الدعم الفني

في حالة وجود مشاكل:
1. التحقق من صلاحيات الاتصال بقاعدة البيانات
2. التأكد من تطابق أسماء المستخدمين وكلمات المرور
3. التحقق من وجود قواعد البيانات المطلوبة
4. مراجعة سجلات الأخطاء (error logs)
5. اختبار الاتصال اليدوي بقواعد البيانات
