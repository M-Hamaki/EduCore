# دليل إعادة تجربة منظومة شؤون العاملين

هذا الدليل مخصص لبيئة قبول معزولة. لا تستخدم أوامر البذر أو الاستعادة على قاعدة `educore` أو أي قاعدة تحتوي بيانات فعلية.

## 1. معلومات الحزمة

- معرف الحزمة: `staff_hr_acceptance_v1`.
- الإصدار: `2026.08.11-2`.
- النطاق: السيناريوهات Q01–Q33.
- الحسابات والبيانات اصطناعية، ورسائل البريد تنتهي بـ `example.test`.
- أكواد العاملين تبدأ بـ `E2099` وتظل منفصلة عن أرقام البصمة `DEMO-BIO-*`.

## 2. شروط البيئة الآمنة

قبل المتابعة تحقق من الآتي:

1. تعمل على نسخة قبول لا على النظام الفعلي.
2. اسم قاعدة البيانات ينتهي حرفيًا بـ `_test`.
3. قيمة `APP_ENV` هي `test` أو `testing`.
4. قيمة `STAFF_HR_TEST_MARKER` هي `integrated-staff-hr`.
5. طُبقت ترحيلات Staff-HR المطلوبة مسبقًا؛ أدوات القبول لا تنشئ أو تعدل الجداول.
6. يوجد حساب إداري أساسي غير تابع للحزمة لتسجيل طلب الاستعادة المدقق.
7. توجد مساحة كافية داخل `storage/test-runtime` لحزمة baseline المؤقتة؛ ينشئها أمر البذر قبل أي بيانات تجريبية.

يفشل الأمر قبل أول كتابة إذا لم تتحقق هذه الشروط أو لم يطابق اسم قاعدة الاتصال اسم القاعدة المطلوب.

## 3. تسليم بيانات الدخول

لا تكتب كلمة مرور القبول في Git أو هذا الدليل أو screenshots أو تقرير النتائج.

- ينشئ مسؤول البيئة كلمة مرور مؤقتة لا تقل عن 12 محرفًا.
- تسلم للمجرب عبر قناة مستقلة مثل مدير كلمات مرور أو رسالة مشفرة محددة الصلاحية.
- تضبط في العملية الحالية فقط باسم `STAFF_HR_ACCEPTANCE_PASSWORD`.
- بعد التسليم أو تغيير صاحب البيئة تُدار دورة تغيير كلمة المرور خارج المستودع.
- لا ترسل Cookies أو CSRF tokens أو session IDs مع الأدلة.

## 4. الشخصيات التجريبية

| المفتاح | اسم الدخول | الدور المستخدم |
|---|---|---|
| `super_admin` | `demo.staffhr.superadmin` | مسؤول النظام ومراجعة السياسات والتدقيق |
| `hr_manager` | `demo.staffhr.hr` | مدير الموارد البشرية |
| `administrative_manager` | `demo.staffhr.admin.manager` | المدير الإداري |
| `direct_manager` | `demo.staffhr.direct.manager` | المدير المباشر |
| `delegate_manager` | `demo.staffhr.delegate` | المدير النائب |
| `worker_teacher` | `demo.staffhr.teacher` | معلم له خدمات عامل |
| `worker_specialist` | `demo.staffhr.specialist` | أخصائي له خدمات عامل |
| `worker_standard` | `demo.staffhr.worker` | عامل إداري |
| `protection_officer` | `demo.staffhr.protection` | مسؤول حماية لبلاغات ارتق العاجلة |
| `finance_operator` | `demo.staffhr.finance` | منفذ الأثر المالي دون بيانات سرية |

كل الحسابات تستخدم كلمة المرور المؤقتة نفسها عند البذر، لكنها لا تظهر في manifest أو مخرجات الأمر.

## 5. تحميل الحزمة

من PowerShell داخل مجلد المشروع، وبعد ضبط قيم البيئة محليًا:

```powershell
$env:APP_ENV = 'test'
$env:STAFF_HR_TEST_MARKER = 'integrated-staff-hr'
$env:STAFF_HR_ACCEPTANCE_PASSWORD = '<تُستلم من القناة الآمنة>'
C:\xampp\php\php.exe tools\staff_hr_acceptance_seed.php --database=<acceptance_name_test> --json
```

احفظ من الإيصال فقط: `dataset_id` و`version` و`batch_id` و`checksum` والأعداد ومعرف baseline. لا تحفظ كلمة المرور ولا مفتاح الحزمة في تقرير عام. إعادة الأمر بالإصدار نفسه تتحقق من الصفوف المملوكة ولا تنشئ نسخًا مكررة.

## 6. رحلة إعادة تجربة مختصرة

1. سجل الدخول بـ`worker_standard`، وافتح خدمات العامل وتأكد أن تغيير معرف العامل في الرابط لا يكشف بيانات غيره.
2. أنشئ إذن حضور متأخر لدوام 07:30 حتى 09:30، عدله قبل الإرسال ثم أرسله.
3. سجل الدخول بـ`direct_manager` ثم `administrative_manager` ثم `hr_manager` ونفذ مراحل القرار حسب المسار المنشور.
4. تحقق أن دخول 09:00 لا يحتسب تأخيرًا، وأن دخول 10:00 يترك 30 دقيقة غير مغطاة.
5. أنشئ إذن انصراف من 12:00 وتحقق أن خروج 12:00 مغطى وخروج 11:45 يترك 15 دقيقة.
6. افتح تقرير العامل، ثم التقرير الشهري؛ يجب أن تتطابق الإجماليات مع تفاصيل الأيام وأن تظهر الإجازة والمأمورية منفصلتين عن الغياب.
7. سجل الدخول بـ`worker_teacher` وتأكد أن خدمات العامل تظهر داخل بوابة المعلم دون التحويل إلى دور employee.
8. أنشئ رسالة ارتق سرية، وتأكد أنها لا تظهر للمدير محل الشكوى وأن الإشعار لا يعرض موضوعها أو مرفقها.
9. راجع الأثر المالي من `finance_operator` دون إظهار تفاصيل طبية أو تأديبية أو محتوى شكوى.
10. راجع التدقيق من `super_admin` وتأكد أن القرار يحفظ صاحبه ومصدره دون كلمات مرور أو جلسات.

للتجربة الكاملة اتبع Q01–Q33 في `specs/004-integrated-staff-affairs/quickstart.md`.

## 7. تسجيل النتيجة

لكل سيناريو سجل: الرمز، الشخصية، وقت البدء والانتهاء، المتوقع، الفعلي، والحالة `passed/failed/blocked`. يسمح بدليل screenshot منزوع الحساسية أو مرجع تقرير أو رقم تدقيق. عند الفشل أضف مرجع عيب دون نسخ SQLSTATE أو stack trace إلى المستخدم.

## 8. استعادة baseline الآمنة

طلبات الأذونات والإجازات وحركات الأرصدة وأحداث البصمة ونسخ الحضور والجزاءات وتذاكر «ارتق» أدلة محتفظ بها ولا يجوز حذفها أو تعطيل triggers الخاصة بها. لذلك لا تغيّر الاستعادة قاعدة القبول المصدر، بل تعيد حزمة baseline الموثقة إلى **قاعدة جديدة غير موجودة** ينتهي اسمها بـ`_test`. يجب أن يكون المنفذ حسابًا إداريًا أساسيًا غير تابع للحزمة:

```powershell
$env:APP_ENV = 'test'
$env:STAFF_HR_TEST_MARKER = 'integrated-staff-hr'
C:\xampp\php\php.exe tools\staff_hr_acceptance_restore.php --database=<acceptance_name_test> --target-database=<fresh_baseline_name_test> --actor-id=<baseline_admin_id> --json
```

تحقق من الإيصال ومن عدم وجود حسابات `demo.staffhr.*` في قاعدة baseline الجديدة قبل توجيه بيئة القبول إليها. إعادة الأمر بالهدف نفسه مقبولة فقط إذا بقيت بصمة القاعدة مطابقة تمامًا؛ أي تغيير يجعل العملية تفشل مغلقة ويستلزم اسم هدف جديدًا. إذا ظهر تعارض ملكية أو بصمة فتوقف ولا تنفذ حذفًا يدويًا.

## 9. قائمة تسليم المستخدم

- [ ] عنوان بيئة القبول واسم قاعدة `_test` موثقان خارج Git.
- [ ] كلمة المرور سلمت بقناة مستقلة ولم تدخل تقريرًا أو screenshot.
- [ ] إصدار الحزمة وchecksum وإيصال آخر بذر مسجلة.
- [ ] Q01–Q33 لها نتيجة أو عيب مانع واضح.
- [ ] استعادة baseline إلى قاعدة جديدة نجحت، ثم نجحت رحلة العامل ← الاعتماد ← التقرير بعد إعادة البذر المقصودة.
- [ ] الحزمة متروكة بالحالة المذكورة في تقرير التسليم.
- [ ] لا توجد بيانات فعلية أو أسرار أو روابط مرفقات خاصة ضمن الأدلة.
