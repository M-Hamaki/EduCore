# سياسة بيانات تهيئة عام دراسي جديد

## الهدف

هذه الوثيقة تصنف بيانات EduCore قبل توسيع `NewYearWizard`. التهيئة ليست نسخًا عامًا لقاعدة البيانات؛ بل إنشاء سياق سنوي جديد مع إبقاء الهوية والمرجعيات، ونسخ الإعدادات القابلة لإعادة الاستخدام بعد إعادة ربط المفاتيح، وعدم نسخ الأحداث والنتائج التاريخية.

## القرار التنفيذي النهائي — 2026-07-18

هذه الفقرة تلغي أي توصية قديمة بخيارات يحددها المستخدم داخل المعالج. السياسة أصبحت ثابتة:

- **ينقل آليًا كمسودة/غير نشط:** الترم والشهر والأسبوع، الفصول وفق خريطة انتقال مراجعة، إسناد المادة للصف، ومخططات التقييم ومكوناتها وقواعد الأسابيع.
- **قيود الطلاب لا تُستنتج من ترتيب الصف أو اسم الفصل:** تحفظ قواعد انتقال صريحة لكل زوج أعوام ولكل صف رسمي، ثم يحفظ قرار مستقل لكل قيد مصدر قبل النسخة الاحتياطية.
- **كل قرار طالب يحمل حالتين مستقلتين:** حالة القيد (`مقيد/منقول/منقطع`) والحالة الدراسية (`مستجد/ناجح ومنقول/راسب/خريج`). لا تُستنتج إحداهما من الأخرى.
- **ينشأ قيد هدف فقط للمقيد الناجح أو الراسب:** الناجح ينتقل إلى الصف المحدد بالقاعدة ويتبع فصل مجموعته عندما يكون التسكين التلقائي مفعّلًا في الخريطة؛ وإن لم يكن له فصل مصدر أو اختير التنظيم اليدوي يبدأ بلا فصل. الراسب يبقى في صفه بلا فصل مع زيادة عداد الإعادة.
- **لا ينشأ قيد هدف** للخريج أو المنقول خارج المدرسة أو المنقطع أو القرار المعلق أو حساب/صف الاختبار. عند التفعيل تعتمد الحالة النهائية على قيد المصدر نفسه ليظل المسار السنوي كاملاً، مع مزامنة ملخص ملف الطالب وحالة الحساب للتوافق.
- **لا ينقل مطلقًا:** الحضور، التقييم السلوكي، الدرجات والـmarks، تقارير النشر، حركات النقل، مطالبات الرسوم والمدفوعات والخصومات، وسجل التدقيق.
- **يبدأ فارغًا لإعداد يدوي:** تكليفات المعلمين، الجدول، تسكين الباص، هيكل الرسوم والأقساط والمديونيات، نوافذ الرصد والتقارير، وصلاحيات التشغيل السنوية.
- لا توجد checkboxes للنسخ. أي صف غير واضح أو طالب بلا تسكين صالح يمنع التنفيذ بدل التخطي.
- التنفيذ لا يفعّل الهدف؛ يلزم backup مجرّب الاستعادة، manifest دائم، تحقق مستقل، ثم تفعيل صريح يقفل المصدر.

## فئات القرار

| الرمز | القرار | المعنى التنفيذي |
|---|---|---|
| P | يبقى كما هو | سجل عالمي/هوية مستمرة، ولا ينشأ له سجل بديل بسبب العام الجديد. |
| C | ينسخ إلى العام الجديد | إعداد سنوي ينسخ بسجل جديد ومفاتيح جديدة، مع حفظ مرجع المصدر عند توفره. |
| N | يبدأ جديدًا | سجل سنوي جديد ينشأ فقط عند حدوث العملية في العام الهدف؛ لا تنسخ صفوف المصدر. |
| H | تاريخي مستمر | سجل حدث أو نتيجة يبقى قابلًا للعرض ولا ينسخ ولا يصفر. |
| R | يعاد بناؤه | بيانات مشتقة أو صلاحية مرتبطة بفصول العام؛ تعاد من المصدر المعتمد بعد remapping. |
| D | قرار أعمال | لا يدخل الترحيل التلقائي قبل اعتماد اختيار واضح في واجهة المعالج. |

## الترتيب الإلزامي للترحيل

1. إنشاء العام الهدف غير نشط وفارغًا، ثم حفظ قواعد انتقال الصفوف الصريحة لزوج العامين.
2. حفظ خريطة الفصول: فصل المجموعة ينتقل إلى الصف الهدف بنفس الاسم افتراضيًا، وتضاف قوالب فارغة لأول صف دخول أو لاستكمال فرق عدد الفصول بين دفعتين؛ يمكن تعديل الاسم والسعة أو تعطيل الإنشاء/التسكين التلقائي قبل التنفيذ.
3. حفظ حالتي القيد والدراسة لكل قيد مصدر، ثم اشتقاق قرار التنفيذ: ناجح، راسب، معلق، خريج، منقول، منقطع، أو مستبعد تجريبي؛ أي قرار معلق أو طالب حقيقي بلا مرحلة/صف يمنع التنفيذ.
4. إنشاء حزمة تعافٍ جديدة بعد الخريطة والقرارات وإثبات استعادتها إلى قاعدة `_test`.
5. نسخ التقويم وإنشاء الفصول المخططة كمسودات مع حفظ علاقة كل فصل بخريطة المصدر في manifest.
6. إنشاء قيود الهدف للمقيدين الناجحين والراسبين مع `academic_status` صريح وربط `source_enrollment_id` و`promotion_decision_id`: الناجح يُسكّن في فصل المجموعة المفعّل، والراسب يبقى بلا فصل.
7. نسخ إسناد المواد ومخططات التقييم المسودة وبناء خرائطها.
8. التحقق المستقل من الأعداد والروابط والـmanifest قبل التفعيل؛ لا تنسخ نتائج أو حركات تاريخية.
9. تسكين الراسبين والناجحين الذين اختير لهم التنظيم اليدوي، وتشغيل الجدول والنقل والمالية لاحقًا عبر ملاكها.

## ما ينفذه المعالج حاليًا وما ينقصه

| المجال | الحالة الحالية |
|---|---|
| قواعد الانتقال وقرارات الطلاب | منفذة صراحة لكل زوج أعوام، مع منع أي قرار غير محسوم. |
| الفصول وخريطة الفصول | منفذة بخريطة مراجعة قابلة لتعديل الاسم والسعة وتعطيل الإنشاء أو التسكين؛ تشمل فصول المجموعات وقوالب صفوف الدخول. |
| ترقية/إعادة/تخرج الطلاب والقيود | منفذة: الناجح يتبع فصل مجموعته المفعّل، والراسب يبقى في صفه بلا فصل؛ الحالات الأخرى موثقة بلا قيد هدف. |
| البيانات التجريبية | منفذة بعلامات قابلة للعكس على المرحلة والصف والفصل وحساب الطالب. يرث الصف تصنيف مرحلته ويرث الفصل تصنيف صفه ومرحلته، وتُستبعد جميع هذه النطاقات صراحة من التهيئة الآمنة. |
| التقويم: ترم/شهر/أسبوع | منفذ مع remap. |
| إسنادات المواد | منفذة كغير نشطة؛ تكليفات المعلمين تبدأ فارغة. |
| مخططات التقييم ومكوناتها | منفذة كمسودات مع قواعد الأسابيع. |
| تسكين الحافلات والأرصدة | لا ينفذهما الترحيل الآمن؛ يبدأان فارغين وفق القرار المغلق. |
| صلاحيات الفصول legacy | غير منفذ، وقد تبقى مرتبطة بفصول المصدر. |
| الجدول الدراسي | غير منفذ. |
| هياكل الرسوم والأقساط ومناطق النقل | غير منفذ. |

## ضوابط التنفيذ والرجوع

- المعالج يعمل على قاعدة غير إنتاجية أولًا، داخل معاملة واحدة ما أمكن، ويقفل المصدر/الهدف منطقيًا أثناء التنفيذ.
- كل خطوة قابلة لإعادة التشغيل أو ترفض هدفًا غير فارغ بوضوح؛ لا تستخدم `INSERT IGNORE` لإخفاء تعارض غير مفهوم.
- يسجل manifest يحتوي المصدر والهدف والخيارات والأعداد وخرائط المعرفات وفاعل العملية، دون أسرار أو بيانات حساسة كاملة.
- التحقق يقارن الأعداد، المراجع اليتيمة، الطلاب المفقودين، الفصول بلا صف، والإسنادات إلى مستخدمين غير نشطين.
- لا يفعّل العام الهدف تلقائيًا. التفعيل خطوة مستقلة بعد تقرير تحقق وموافقة الإدارة.
- الرجوع قبل التفعيل يحذف فقط الصفوف التي أنشأها manifest في العام الهدف بترتيب عكسي؛ لا يعدّل تاريخ المصدر.

## قرارات أُغلقت قبل البرمجة

1. تكليفات المعلمين تبدأ فارغة للمراجعة.
2. الجدول يبدأ فارغًا.
3. الرسوم ومناطق النقل وتسكين الباص لا تنقل تلقائيًا.
4. الدين يبقى على مطالبة المصدر حتى اعتماد نموذج محاسبي مستقل؛ لا ينشئ المعالج مطالبة افتتاحية.
5. رصيد إجازات الموظفين خارج حدود تهيئة العام الدراسي.
6. محتوى الذكاء الاصطناعي العام يبقى كما هو، ولا تُنسخ نتائجه أو أحداثه التاريخية.
