# الأسئلة الشائعة

## ما هو EduCore؟

EduCore منصة مفتوحة المصدر لإدارة المدارس، مصممة أولاً للعربية وتدعم RTL والبوابات المتخصصة والتقييمات والحضور والتقارير والتكاملات القابلة للتهيئة.

## هل يمكن تشغيله على خادم المؤسسة؟

نعم. المشروع self-hosted، ويحتاج PHP 8.0+ وMySQL أو MariaDB وامتدادات PHP الموضحة في `composer.json`. راجع `CONTRIBUTING.md` و`.env.example`.

## كيف أبدأ إعدادًا جديدًا؟

```bash
composer install
cp .env.example .env
```

أنشئ قاعدة اختبار أو تطوير منفصلة، ثم اضبط `APP_URL` وبيانات قاعدة البيانات ومفاتيح التكامل الخاصة بنشرك.

## كيف أضبط اسم المؤسسة وبيانات الدعم؟

استخدم `ORGANIZATION_NAME` و`SUPPORT_EMAIL` و`SUPPORT_PHONE` في `.env`. لا تضع هذه القيم في الكود أو في ملفات التوثيق العامة.

## كيف أضبط Microsoft SSO وTeams؟

سجّل Redirect URIs الخاصة بنشرك في Entra ID، ثم اضبط `AZURE_REDIRECT_URI` و`AZURE_TEAMS_REDIRECT_URI` و`TEAMS_APP_ID_URI`. استخدم `teams/manifest.example.json` كنقطة بداية، ولا تلتزم بنسخة الإنتاج.

## هل توجد حسابات افتراضية؟

لا يوجد حساب افتراضي جاهز. يمكن للمشغل اختيار الحساب الأول عبر `INITIAL_SUPER_ADMIN_USERNAME` أثناء bootstrap، أو إنشاء الحساب بالطريقة الموثقة في بيئته.

## أين أبلغ عن مشكلة أمنية؟

لا تنشر تفاصيل الثغرات في issue عام. اتبع [سياسة الأمان](../SECURITY.md) وأرسل البلاغ عبر GitHub Security Advisories باستخدام بيانات اصطناعية فقط.

## هل يمكن إرسال بيانات الطلاب في issue أو تقرير خطأ؟

لا. استخدم بيانات demo اصطناعية، واحذف الأسماء والبريد والأرقام والملفات وسجلات الإنتاج قبل مشاركة أي مثال.

## كيف أساهم؟

ابدأ بقراءة [دليل المساهمة](../CONTRIBUTING.md)، ثم أنشئ فرعًا صغيرًا وشغّل الاختبارات المناسبة قبل فتح Pull Request.
