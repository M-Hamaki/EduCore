## Confirmed Security Baseline — 2026-07-13

- Runtime DDL findings: zero.
- Unreviewed POST-without-CSRF candidates: zero under strict architecture audit.
- Seven narrowly reviewed non-CSRF paths are governed by `tools/architecture_csrf_exemptions.json`: six read-only paths and one verified Microsoft bearer-token exchange.
- Public activity and online-exam writes require an anonymous session-bound CSRF token.

Legacy public files remain dual-readable through the controller during migration; active admin consumers no longer emit direct attachment URLs. Upload validation rejects dangerous double extensions and MIME mismatches, while external material-preview links are generated from `APP_URL`; the read-only stored-path audit found no localhost URLs in known upload columns on 2026-07-16.
- Future upload paths are governed by the mandatory `AGENTS.md` upload section, `docs/file-upload-standard.md`, and the reviewed `tools/upload_policy_manifest.json`; `composer upload-policy-audit` rejects unreviewed direct movers or removed contract markers, and GitHub Actions runs the complete `composer quality` gate.

- Lesson generation uses **per-call model tiering** (`config/ai_config.php::getTierModel()`): `GeminiAI::generateContent()` honors `options['model']` to override the default model for one request without changing the provider's default. `LessonGenerator::tierOptions($tier,$overrideMaxTokens)` builds the options; heavy-tier generators (`generateLessonPlan`, `generateQuestionBank`, `generateEducationalStories`, `generateCustomContent`, `generatePowerPointSlides`) route to `gemini-3.5-flash` while light-tier generators (`generateClassActivities`, `generateVisualMaterials`, `generateMindMaps`, `generateLessonSummary`) route to `gemini-3.1-flash-lite`. - **Model availability constraint (verified July 2026):** Google blocks the 2.x generation (e.g. `gemini-2.5-flash`) for **new users** on the free tier with HTTP 404 "no longer available to new users", even though the model still appears in `models.list`. The 2.x models are also scheduled for sunset on 2026-10-16. The correct way to discover currently-available model IDs is the `models.list` endpoint (`https://generativelanguage.googleapis.com/v1beta/models?key=KEY`) — presence there does **not** guarantee free-tier access; a smoke test is required.
- **Latency constraint & model selection (verified July 2026):** `gemini-3.5-flash` is a **thinking model** — it spends 476+ `thoughtsTokenCount` on reasoning before answering, yielding **highly variable latency (4–120s)** and occasional HTTP 503 "high demand" with 90s timeouts. `gemini-3.1-flash-lite` uses **0 thoughts tokens** and completes in **~2.5s** even for heavy requests (`maxTokens=16384`). Therefore both heavy and light tiers are now pinned to `gemini-3.1-flash-lite` (overridable via `GEMINI_MODEL_HEAVY`/`GEMINI_MODEL_LIGHT` if maximum quality is later required at the cost of speed). To match the faster model: all inter-section `usleep`/`sleep` delays in `LessonGenerator::generateAll()` were removed (flash-lite completes requests before rate-limit accumulation), and `GEMINI_TIMEOUT` was reduced from 120s to 60s (the long timeout only prolonged failure waits under 503 load). Expected full-lesson generation time dropped from ~100s to ~15–20s (≈6× faster).
- **PowerPoint generation pipeline (fixed July 2026):** Two code paths exist — the dedicated standalone endpoint (`teacher/ajax/generate_powerpoint_only.php` → `LessonGenerator::generatePowerPointSlides()` → `LessonPowerPointGenerator::generateFromSlides()`) is the **good path** producing student-facing slides; the full-lesson endpoint (`teacher/ajax/generate_lesson.php`) now also uses this dedicated path with a fallback to the legacy `LessonPowerPointGenerator::generate()` (which reverse-engineers slides from `lesson_plan` teacher-prep metadata — lower quality). Three defects were fixed: (1) a critical bug where `$prompt = AIPrompts::getPowerPointSlidesPrompt(...)` in `LessonGenerator::generatePowerPointSlides` was commented out by a stray inline `//` on the same line, so the AI received raw content with **zero instructions** — moved to its own line; (2) `LessonPowerPointGenerator::$fontName` was hardcoded to `Calibri` which has no Arabic glyph coverage, so Arabic slides rendered with broken shaping — now dynamic via `applyFontForLanguage()` (Arial for RTL `ar/he/fa/ur`, Calibri for Latin); (3) the `ar` branch of `getPowerPointSlidesPrompt` built `$limitedContentNote_ar` but never appended it (unlike `fr`/`de`/`en`) — now appended. The prompt itself (`getPowerPointSlidesPrompt`) is well-designed with an explicit per-slide JSON schema (`{type, title, points}`) and a mandatory final `questions` slide; quality issues were entirely in the plumbing, not the prompt.
- **PowerPoint fallback decontaminated (fixed July 2026):** The fallback path `LessonPowerPointGenerator::generate()` → `buildLessonSlides()` was producing **teacher-prep content** in slides instead of student-facing lesson content. The contamination (originating from `lesson_plan` keys) was removed: (1) the cognitive/affective/psychomotor objectives taxonomy (`🎯 الأهداف المعرفية` / `💡 الوجدانية` / `✋ المهارية`) was replaced with a **flat student-facing objectives list** prefixed by "بعد هذا الدرس سيكون الطالب قادراً على:" — all objectives from any bucket are merged into one list without showing the taxonomy itself; (2) "دور المعلم" / "دور المتعلم" injection inside lesson phases was removed; (3) three whole slides were deleted — "استراتيجيات التدريس", "الوسائل والمصادر التعليمية", "الواجب المنزلي" (all teacher-prep metadata); (4) the "نشاط صفي" slide injected from `class_activities` in `generate()` was removed; (5) the "التقويم" slide was renamed to "أسئلة للتفكير" / "Points to Think About" to reframe it as student-facing. What remains in the fallback: introduction, lesson phases (content/description only), the reframed thinking questions, and the lesson summary — all student-facing. The primary path (`generateFromSlides`) and the `getPowerPointSlidesPrompt` prompt were already clean and forbade teacher-prep content explicitly; no change was needed there.
- **PowerPoint primary/fallback contract bug + download session fix (fixed July 2026):** Two more PPT defects. (a) **Return-shape mismatch:** `generate_lesson.php` checked `!empty($dedicatedSlides['slides'])` but `LessonGenerator::generatePowerPointSlides()` returns `$jsonData['slides']` (the array of slides directly, not wrapped under a `slides` key). So the primary path's success check was always false → always fell through to the decontaminated fallback, never producing the rich AI-generated slides. Fixed by checking `!empty($dedicatedSlides) && is_array($dedicatedSlides)` and passing `$dedicatedSlides` directly as the `slides` value. The contract chain is now aligned: prompt asks for `{type,title,points}` per slide → generator returns the slides array → caller passes it as `['slides' => $dedicatedSlides]` → `generateFromSlides` reads `$lesson['slides']`. (b) **Download failure (session regeneration):** `teacher/lesson_download.php` went through `session_config.php` which calls `session_regenerate_id(true)` every 30 min (`SESSION_REGENERATE_INTERVAL`); when a teacher clicked the download link after that window, the server invalidated the old cookie, but the browser still sent the old cookie → empty session → redirect to login → "download failed". Fixed by setting `$_ENV['SESSION_REGENERATE_INTERVAL'] = PHP_INT_MAX` (and `putenv`) **before** requiring `session_config.php` in `lesson_download.php` only — this disables regeneration for the download endpoint while preserving the idle timeout (1h) security check. The download endpoint is session read-only and needs no ID rotation.
- **Archive view parity & custom-content styling (fixed July 2026):** `teacher/lesson_view.php` (archive) previously lost two generated sections that the generation view showed — (a) `educational_stories` was decoded by neither PHP nor `window.generatedData` and had no tab/container, and (b) the PowerPoint download button was missing entirely.
