## ✅ الإصلاح #3 — إيقاف عرض الأخطاء في الإنتاج

### المشكلة
ملف `index.php:6-8` كان يفعّل `display_errors=1` بشكل ثابت مع تعليق `// Production friendly` متناقض. هذا يكشف مسارات الملفات وأسرار قاعدة البيانات لأي زائر عند حدوث خطأ PHP.

### الإصلاح
تطبيق **نظام كشف بيئي** عبر متغير `APP_ENV` في `.env`:

| الملف | التغيير |
|-------|---------|
| `.env` | إضافة `APP_ENV=production` |
| `.env.example` | إضافة `APP_ENV=development` (افتراضي) |
| `index.php` | استبدال 3 أسطر ثابتة بكتلة بيئية تقرأ `env('APP_ENV')` |

**السلوك بعد الإصلاح:**
- `APP_ENV=production` (الإنتاج) → `display_errors=0`, `log_errors=1` — الأخطاء تُسجّل في ملف log الخادم فقط
- `APP_ENV=development` (التطوير) → `display_errors=1` — عرض كامل كما كان

**ملاحظة:** `config/env_loader.php` لم يحتج أي تعديل — الدالة `env()` كانت متاحة بالفعل.

### التحقق
```

```

## ✅ المشكلة #1 — كلمات المرور (تم الحسم وتطبيق تحصين أمني)

### وصف المشكلة
كلمات المرور تُشفَّر بـ AES-256-CBC (قابل للعكس) وتُخزَّن كـ `base64(iv)::ciphertext`.

### القرار والتطبيق
بناءً على متطلبات العمل الخاصة بالمشروع، **تم إقرار الإبقاء على تشفير كلمات المرور باستخدام AES-256-CBC كـ (سلوك مقصود بالتصميم / Design Intent)** لتمكين الأدمن (Admin) والمدير/المشرف (Supervisor) من عرض ونسخ كلمات المرور للطلاب والمعلمين عند الحاجة.

لتحصين هذا الخيار وتأمين عملية عرض كلمات المرور، تم تطبيق الإجراءات الأمنية التالية:
1. **تقييد فك التشفير برمجياً:** تم تعديل ملف الفئة `User` في `classes/user.php` بحيث يتم حجب كلمة المرور وإرجاع قيمة فارغة `''` لجميع الأدوار والمستويات، ولا يتم فك تشفير كلمة المرور إلا إذا كان دور المستخدم الفعلي المسجل في الجلسة `$_SESSION['role']` هو `admin` أو `supervisor`.
2. **تأمين واجهات الـ AJAX:** تم تحديث الواجهات الخلفية (Endpoints) مثل `includes/ajax_handlers.php` لحجب كلمات المرور من الاستجابات تماماً، وتوفيرها حصراً للأدمن والمدير المصرح لهما.
3. **منع فك التشفير غير الضروري:** تم تعديل منطق تسجيل الدخول ليقوم بالتحقق مباشرة عبر `verifyStoredPassword` دون فك التشفير وتخزين كلمة المرور مكشوفة في الذاكرة بشكل غير ضروري.
