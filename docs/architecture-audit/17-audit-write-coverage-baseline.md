## تفسير الأرقام

- `مرشح للكتابة` يعني أن الفاحص وجد SQL كتابة أو استدعاء خدمة يحمل اسمًا دالًا على تغيير حالة.
- `تعلن ActivityLog` يعني وجود استدعاء تسجيل في الملف؛ لا يثبت وحده أن كل فرع ناجح أو فاشل مسجل أو أن التسجيل داخل transaction الصحيحة.
- `تحتاج مراجعة` لا تعني تلقائيًا وجود عيب؛ قد تكون الكتابة داخل خدمة أخرى مسجلة، أو SQL في fixture/comment، أو cache تقني لا يمثل حدث أعمال.
- لا تظهر مساحة في الجدول عندما لا يجد الفاحص مرشحًا؛ هذا ليس إثباتًا أنها بلا عمليات كتابة ديناميكية.

## قواعد إغلاق الجرد

لا ينتقل ملف من `تحتاج مراجعة` إلى `مغطى` إلا بأحد الأدلة التالية:

1. اختبار مسار يثبت أن الكتابة الناجحة تنتج حدثًا صحيحًا.
2. عقد خدمة يملك الكتابة والتدقيق داخل حد واضح، مع اختبار contract.
3. تصنيف موثق بأن الكتابة تقنية غير تجارية، مع سياسة observability مناسبة.
4. إثبات أن النتيجة false positive مع تحديث الفاحص دون إخفاء مرشحين حقيقيين.

الهدف النهائي هو صفر ملف غير مصنف، وليس مجرد صفر نتيجة من الفاحص.

## ترتيب المراجعة

1. المصادقة والصلاحيات والحسابات.
2. الدرجات والتقييم والحضور والتقارير المنشورة.
3. الماليات والمدفوعات والرواتب والسلف والخصومات.
4. الطلاب والعاملون والارتباطات متعددة الجداول والمرفقات.
5. API وAJAX وبوابات المعلم والمتخصص والمشرف.
6. الخدمات الداخلية والعمليات الجماعية والاستيراد والمهام المجدولة.
