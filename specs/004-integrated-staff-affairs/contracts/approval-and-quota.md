# عقد الموافقات والحصص

## 1. أوامر دورة الطلب

### إنشاء مسودة

```text
createDraft(actor, requestType, payload) -> Request
```

- العامل ينشئ طلبه لنفسه؛ الإداري يحتاج قدرة صريحة للإنشاء بالنيابة مع تسجيل ذلك.
- المسودة لا تحجز حصة ولا ترسل إشعارًا.

### تقديم

```text
submit(actor, requestId, expectedVersion, idempotencyKey) -> SubmissionResult
```

داخل معاملة واحدة:

1. قفل الطلب والتحقق من النسخة والملكية.
2. حل السياسة والتعيين والمسار عند بداية فترة الاستحقاق للطلب المستقبلي، ثم تثبيتها.
3. التحقق من الفترات والتداخل والمرفقات والقواعد.
4. قفل حساب الحصة/الرصيد وحجز المطلوب.
5. إنشاء instance وخطوات ومعتمدين snapshots.
6. نقل الحالة إلى `pending_approval`.
7. تسجيل التدقيق وإنشاء حدث إشعار داخل Outbox.

### قرار

```text
decide(actor, stepId, decision, comment, expectedVersion, idempotencyKey) -> DecisionResult
```

- يعاد التحقق أن actor معتمد أصلي أو نائب ساري لهذا النوع والنطاق.
- يمنع self-approval وتعارض المصالح.
- `SELECT ... FOR UPDATE` أو optimistic lock يمنع قرارين متزامنين.
- تكرار المفتاح يعيد نفس النتيجة؛ اختلاف القرار بالمفتاح نفسه خطأ.
- الرفض ينهي المسار ويحرر الحجز.
- اكتمال آخر موافقة يحول الحجز إلى استهلاك وينشئ أثر إعادة احتساب الحضور.
- إذا كان actor نفسه محلولًا في مرحلتين، تطبق `same_actor_rule`: دمج المرحلتين أو طلب بديل؛ ولا يحتسب القرار نفسه مرتين ضمنيًا.
- مرحلة `quorum` تحدد مسبقًا النصاب وقاعدة التعادل وأثر أول رفض، ولا تستنتج النتيجة من ترتيب وصول القرارات.

### سحب أو إلغاء

```text
withdraw(actor, requestId, reason, expectedVersion) -> Result
requestCancellation(actor, requestId, reason) -> Result
```

- قبل أول قرار: السحب يحرر الحجز.
- بعد اعتماد نهائي: لا تعديل أو حذف؛ ينشأ مسار إلغاء/تصحيح.
- إذا أثّر الطلب في تقرير مقفل أو راتب، تُنشأ آثار عكس منفصلة ولا يُلغى المصدر صامتًا.
- انتهاء الخدمة أثناء طلب جارٍ ينقل الطلب إلى transition تحدده السياسة (`cancelled_due_to_service_end`, `continue_for_record`, أو مراجعة HR)، مع تحرير أي حجز غير مستحق.

## 2. حل مسار الاعتماد

الافتراضي:

1. المدير المباشر وقت الإرسال.
2. المدير الإداري للمدرسة/القوة.
3. مراحل إضافية منشورة يحددها السوبر أدمن.

قواعد:

- لا مدير مباشر: المسار يتبع سياسة `fail_closed` أو بديلًا مسمى؛ لا يعتمد Admin عشوائيًا.
- شكوى ضد المدير: يستبعد المدير وأي طرف متعارض، وتنتقل لفريق/مستوى مستقل.
- المدير الغائب: نائب ساري أو تصعيد بعد SLA.
- تغيير المدير لاحقًا لا يعيد رسم الطلب الجاري؛ إعادة الإسناد قرار مدقق.
- الطلب المستقبلي يحل المدير وفق التعيين النافذ عند بداية الاستحقاق، لا وفق يوم الإرسال فقط.
- صلاحية المعتمد `review_assigned` لا تمنحه صفحة HR كاملة ولا رؤية طلبات غير مسندة.

## 3. سياسة الحصة

كل سياسة إذن قد تحدد:

- عدد الطلبات في الشهر.
- أقصى دقائق للطلب.
- أقصى مجموع دقائق في الشهر.
- ما إذا كان الطلب بأثر رجعي مسموحًا.
- هل المعلق يحجز الحصة: الافتراضي نعم.
- قواعد تقسيم الطلب العابر لشهرين حسب المنطقة الزمنية للمدرسة.

الحركات:

| الحدث | الحركة |
|---|---|
| تقديم | `reserve` |
| اعتماد نهائي | `consume` للحجز |
| رفض/سحب/انتهاء | `release` |
| إلغاء معتمد | `reverse` وفق أثره |
| تصحيح إداري | `adjust` بسبب وموافقة |

## 4. التزامن

- يقفل حساب `(staff, permission_type, period)` قبل التحقق والتسجيل.
- unique على `idempotency_key` وعلى الحركة المنطقية للطلب.
- إذا استهلك طلبان آخر حصة بالتزامن، ينجح واحد ويرجع الآخر `QUOTA_EXCEEDED`.
- تحديث الحالة مشروط بـ `expectedVersion`; عدم مطابقة الصف = `STALE_REQUEST`.
- لا يعتمد قرار بعد اكتمال الخطوة؛ يرجع `ALREADY_DECIDED` مع القرار الفعلي.

## 5. صلاحيات وخصوصية

- العامل: طلباته وأرصدته فقط.
- المدير: الطلبات المسندة له والحقول اللازمة للقرار فقط.
- HR المخول: السياسات والحالات التشغيلية حسب القوة/النطاق.
- السوبر أدمن: نشر السياسات والمسارات وتعيين المعتمدين، لا اعتماد طلبه لنفسه.
- المستند الطبي لا يعرض للمدير إلا إذا كانت السياسة تمنحه الحقل؛ يمكن عرض «تم التحقق» بدل الملف.

## 6. رسائل الأخطاء

الخدمة تعيد رمزًا ورسالة عربية وحقلًا اختياريًا، ولا تعرض SQL:

| الرمز | الرسالة المقترحة |
|---|---|
| `QUOTA_EXCEEDED` | تجاوزت الحد الشهري المسموح لهذا النوع. |
| `DURATION_EXCEEDED` | مدة الطلب أكبر من الحد المسموح. |
| `OVERLAP_DETECTED` | توجد إجازة أو إذن متداخل مع هذه الفترة. |
| `APPROVER_NOT_CONFIGURED` | لا يمكن إرسال الطلب قبل تعيين جهة الاعتماد. |
| `NOT_ASSIGNED_APPROVER` | هذا الطلب غير مسند إليك للمراجعة. |
| `SELF_APPROVAL_FORBIDDEN` | لا يمكن اعتماد طلبك الشخصي. |
| `DUPLICATE_STAGE_ACTOR` | لا يمكن احتساب قرار الشخص نفسه في أكثر من مرحلة دون قاعدة معتمدة. |
| `QUORUM_UNRESOLVED` | لم يكتمل نصاب المرحلة أو لم تُحسم نتيجة التعادل. |
| `STALE_REQUEST` | تغير الطلب منذ فتحه؛ حدّث الصفحة ثم أعد المحاولة. |
| `PERIOD_LOCKED` | الفترة مقفلة؛ يلزم طلب إعادة فتح أو تصحيح. |
| `SERVICE_ENDED` | تغيرت حالة خدمة العامل؛ تمت إحالة الطلب للمراجعة وفق السياسة. |

## 7. أثر القرار

- اعتماد إذن/إجازة ينشر `StaffCoverageApproved`.
- الإلغاء ينشر `StaffCoverageReversed`.
- Attendance يستهلك الحدث idempotently ويعيد حساب الأيام المتأثرة.
- Notifications تنشئ رسالة محايدة داخل الصندوق ثم تحاول Push.
- فشل Push لا يلغي القرار التجاري.
