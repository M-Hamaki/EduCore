# عقد حزمة القبول والتسليم

## 1. الهدف

توفير بيئة بيانات تجريبية ثابتة وآمنة يجرب عليها المنفذ جميع العمليات من المتصفح، ثم تبقى جاهزة للمستخدم لإعادة التجربة بعد التسليم.

## 2. شرط العزل

قبل أي تحميل أو استعادة يجب إثبات أحد الشرطين:

- اسم قاعدة البيانات ينتهي بـ `_test`؛ أو
- البيئة تحمل marker demo مصرحًا وموقعًا من إعداد محلي غير محفوظ في المستودع.

عند الشك تفشل العملية قبل أول كتابة. لا يسمح بتجاوز الحارس بوسيط عام أو تعديل اسم داخل الطلب.

## 3. عقد التحميل

```text
seedAcceptanceDataset(datasetKey, version, target, idempotencyKey)
  -> { batchId, entityCounts, checksum, personas }
```

- كل سجل يحمل batch/manifest ownership واضحًا.
- إعادة المفتاح والإصدار نفسيهما تعيد النتيجة ولا تكرر البيانات.
- القيم شخصية لكنها وهمية، ولا تستخدم رقمًا قوميًّا أو هاتفًا أو بريدًا أو مرفقًا حقيقيًا.
- كلمات المرور وtokens لا تدخل fixture أو manifest أو التقرير.
- فشل التدقيق أو أي كيان إلزامي يلغي الدفعة.

## 4. عقد الاستعادة

```text
restoreAcceptanceBaseline(datasetKey, version, expectedChecksum, target)
  -> { restoredCounts, checksum, exceptions }
```

- الاستعادة تستهدف entity refs المملوكة للحزمة فقط.
- لا `TRUNCATE` ولا حذف واسع ولا اعتماد على prefix نصي وحده.
- الموارد الرسمية داخل الحزمة تعكس/تعاد وفق سياساتها، ولا تكسر قيود التدقيق.
- إذا تغير سجل تابع بسبب ارتباط غير تجريبي، تتوقف الاستعادة وتصدر exception بدل حذفه.

## 5. عقد تجربة المتصفح

كل سيناريو يسجل:

- `scenario_id` ونسخة الحزمة.
- persona والدور الفعال.
- خطوات البداية والنهاية.
- النتيجة المتوقعة والفعلية.
- `passed`, `failed`, أو `blocked`.
- دليل غير حساس: screenshot أو مرجع تقرير أو audit reference.
- issue مرجعي عند الفشل.

الرحلات الحرجة:

1. العامل يطلب، يعدل قبل الإرسال، يرسل، يتابع، ويلغي وفق السياسة.
2. المدير المباشر والإداري يوافقان/يرفضان ضمن نطاقهما.
3. HR يصحح استثناءً ويعيد الحساب ويقفل/يعيد فتح الفترة.
4. Finance يستقبل fact ويعتمده أو يعكسه دون تفاصيل سرية.
5. السوبر أدمن ينشر السياسة ويضبط المسار ويراجع التدقيق دون اعتماد ذاتي.
6. العامل يراجع التقرير والرصيد والقرار ويستخدم ارتق.

## 6. بوابة التسليم

لا تعتبر الميزة جاهزة حتى تتوافر:

- بيئة قبول قابلة للفتح.
- dataset وحسابات personas موجودة.
- دليل عربي قابل للاتباع.
- طريقة آمنة مستقلة لتسليم بيانات الدخول.
- baseline مجرب بعد اكتمال الاختبارات.
- تقرير نتائج وأدلة وعيوب معروفة.
- إثبات أن المستخدم يستطيع إعادة رحلة إذن كاملة بعد الاستعادة.

## 7. ما يبقى للمستخدم

- بيانات الحزمة في آخر حالة اختبار ناجحة أو baseline وفق ما يذكره تقرير التسليم.
- الحسابات التجريبية وصلاحياتها.
- السيناريوهات والنتائج المتوقعة.
- snapshot/manifest ووسيلة الاستعادة المحددة النطاق.
- لا تبقى أسرار في Git أو screenshots أو سجل التدقيق.
