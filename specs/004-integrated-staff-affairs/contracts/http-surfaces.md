# عقد الأسطح والصفحات

## 1. المداخل الحالية التي يجب الحفاظ عليها

| المسار | دوره أثناء الترحيل |
|---|---|
| `admin/hr_center.php` | مركز موحد وadapter للملخصات وصندوق المعاملات؛ يضيف خطًا زمنيًا موجزًا وتنبيهات انتهاء في `display|official` دون كشف محتوى الأدلة |
| `admin/staff_shifts.php` | إدارة الدوام؛ ينتقل تدريجيًا إلى السياسات المؤرخة |
| `admin/staff_attendance.php` | متابعة اليوم والاستثناءات |
| `admin/staff_biometric_import.php` | استيراد batch وربط الهوية |
| `admin/biometric_devices.php` | إدارة الأجهزة |
| `admin/staff_attendance_reports.php` | واجهة تقارير متوافقة للمحرك الرسمي |
| `admin/permissions.php` | إدارة الأذونات والسياسات |
| `admin/leaves.php` | إدارة طلبات الإجازة |
| `admin/leave_balances.php` | دفتر الأرصدة والتسويات |
| `admin/disciplinary.php` | adapter إلى القضايا والتظلمات |

لا تتغير أسماء الحقول أو IDs أو actions أو CSRF أو صيغ JSON القديمة إلا بخطة توافق واختبار caller.

الأسماء مقترحة وتُراجع قبل التنفيذ؛ لا تُنشأ في مرحلة الخطة.

## 3. الخدمة الذاتية

- لا directory دور جديد ولا auth stack جديد.
- يضاف component/adapter موحد إلى البوابات الحالية لمن لديه أهلية عامل.
- الأقسام:
  - ملخص دوامي وبصماتي.
  - طلب مراجعة/تصحيح يوم حضور.
  - طلب تبديل وردية أو حضور بديل عندما تسمح السياسة.
  - طلب إذن.
  - طلب إجازة ورصيدي.
  - طلباتي وحالات الاعتماد.
  - ارتق.
  - القرارات والتظلمات الخاصة بي.
- العامل يرى نفسه فقط، ويمنع تغيير `staff_id` من الطلب.
- اليوم بلا بصمة لا يعرض «بعذر» لمجرد وجود إذن، وتظهر حالة التصحيح ومراجعه بوضوح.

## 4. صندوق المدير

- Widget عند تسجيل الدخول: عدد الطلبات المسندة والمتأخرة.
- القائمة تعرض المسند لهذا المدير فقط، لا كل طلبات المدرسة.
- القرار يحتاج CSRF و`expected_version` وcomment عند الرفض.
- فتح المستندات الحساسة يخضع لقدرة حقلية منفصلة.
- الاعتماد لا يمنح المستخدم دور Admin كاملًا.

## 5. نمط HTTP

### HTML

- GET للعرض والفلاتر.
- POST للكتابة مع CSRF.
- نجاح POST يستخدم PRG ورسالة عربية مفهومة.
- خطأ التحقق يعيد الحقول غير الحساسة ورسالة بجوار الحقل.

### AJAX/JSON

صيغة النجاح:

```json
{
  "ok": true,
  "data": {},
  "message": "تم حفظ الطلب بنجاح.",
  "version": 3
}
```

صيغة الخطأ:

```json
{
  "ok": false,
  "error": {
    "code": "QUOTA_EXCEEDED",
    "message": "تجاوزت الحد الشهري المسموح لهذا النوع.",
    "field": "duration_minutes",
    "details": {}
  }
}
```

- لا تظهر SQLSTATE أو اسم index أو stack trace للمستخدم.
- duplicate key معروف يتحول إلى رسالة المجال المناسبة.
- `409` للتعارض/نسخة قديمة، `422` للتحقق، `403` للصلاحية، `404` لغير الموجود ضمن النطاق.

## 6. قواعد الواجهة

- التصميم يتبع `admin/ui_preview.php` والطبقة المركزية.
- لا CSS أزرار داخل الصفحات، ولا SweetAlert أو `confirm()`.
- العمليات النهائية تستخدم Bootstrap modal وسببًا واضحًا.
- الجداول الحرة تستخدم `admin-filter-bar` و`admin-list-surface`.
- كل فلتر تقرير يعرض بوضوح الفترة والقوة والمسمى والمجموعة والشخص.
- التقرير يوضح مقام النسبة، وقت الاحتساب، نسخة التقرير، وحالة الإقفال.

## 7. مصفوفة الرؤية

| المستخدم | ما يراه |
|---|---|
| العامل | بياناته وطلباته وأرصدته ورسائله فقط |
| المدير المباشر | طلبات مرؤوسيه المسندة ضمن فترة علاقته |
| المدير الإداري | المرحلة المسندة ونطاق المدرسة/القوة فقط |
| HR | التشغيل والسياسات وفق القدرة والنطاق |
| Finance | facts والمرجع اللازمان للأثر المالي، لا تفاصيل الشكوى |
| Super Admin | الإعداد والنشر والتعيين والتدقيق، مع منع self-approval |

## 8. الأمان والتدقيق

- كل admin entrypoint يتحقق من الجلسة قبل GET/POST/AJAX.
- كل POST/AJAX يتحقق من CSRF.
- كل output من المستخدم يمر بـ `htmlspecialchars`.
- روابط التنزيل تحمل resource id وتتحقق من الصلاحية، لا مسارًا مباشرًا.
- التصدير يحترم نطاق المستخدم ويمنع CSV formula injection.
- لا يُسجل محتوى الشكوى أو التقرير الطبي في رسائل الخطأ أو Push.
- مسار شكوى الخطر الفوري يعرض تأكيد استلام محايدًا ولا يكشف فريق الحماية أو المشكو في حقه لغير المخولين.
- كل طلب محمي يعيد التحقق من حالة الخدمة وعلاقة المدير؛ فتح الصفحة سابقًا لا يضمن استمرار الصلاحية.
